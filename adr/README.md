# Архитектурные решения (ADR)

Каждое значимое техническое решение проекта описано отдельным документом: почему выбрали именно так,
что рассматривали вместо этого и чем за это платим. Документы фиксируют **причину** решения, а не
пересказывают код: код меняется, причина остаётся полезной.

## Формат

| Раздел                 | Что содержит                                          |
| ---------------------- | ----------------------------------------------------- |
| **Проблема**           | Требования и ограничения, из-за которых возник вопрос |
| **Варианты**           | Альтернативы, у каждой — плюсы и минусы               |
| **Решение**            | Что выбрано, с конкретными деталями реализации        |
| **Почему**             | Аргументы, привязанные к проблеме, а не общие слова   |
| **Последствия**        | Что получаем и чем платим                             |
| **Когда пересмотреть** | Условия, при которых решение перестанет быть верным   |

## Как добавить новое решение

1. Взять следующий свободный номер и назвать файл `<номер>-<короткое-имя>.md` латиницей.
2. Заполнить все шесть разделов. Самый важный — «Варианты»: если рассмотрена одна альтернатива, значит
   решение не обсуждалось.
3. Добавить строку в индекс в тематический блок.
4. В разделе «Когда пересмотреть» указать условие, а не дату: решение пересматривают при изменении
   требований, а не по календарю.
