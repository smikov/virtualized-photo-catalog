# ADR 004: Доступ к глобальному состоянию из нижних слоёв

**Статус:** принято

## Проблема

Типизированные хуки стора (`useAppDispatch`, `useAppSelector`) требуют типа корневого состояния
(`RootState`) и типа dispatch. Оба выводятся из конкретного стора, который собирается в слое `app`, —
самом верхнем по правилам ADR 002.

Отсюда противоречие: хуки нужны фичам и странице, но всё, что они импортируют, лежит выше их по слоям.
Без явного решения это превращается либо в нарушение границ «по факту», либо в неудобную передачу
`dispatch` через пропсы.

## Варианты

### A. Запретить нижним слоям доступ к стору вообще

**Плюсы:** границы слоёв идеальны на бумаге; компоненты становятся «чистыми» и легко тестируются.

**Минусы:** приходится прокидывать `dispatch`, селекторы и данные через пропсы через все уровни; на
практике это либо prop drilling, либо свой контекст — то есть тот же глобальный доступ, но написанный
руками.

### B. Хуки в `shared` с импортом типа состояния из `app`

**Плюсы:** импорты выглядят «правильно» — все тянут хуки из нижнего слоя.

**Минусы:** `shared` начинает знать про `app`, то есть граница нарушается по существу, а не по форме.
Type-only импорт не создаёт рантайм-цикла, но архитектурная зависимость остаётся. Второй вариант — руками
дублировать агрегатный тип состояния в `shared`: гарантированное расхождение при добавлении нового среза.

### C. Разрешить нижним слоям ровно один путь — `@/app/store`

**Плюсы:** один узкий и явный контракт; всё остальное из `app` по-прежнему запрещено; правило проверяется
линтером.

**Минусы:** формально это исключение из правила «сверху вниз»; исключение нужно описать в конфигурации,
иначе оно превратится в «можно всё».

## Решение

В конфигурации ESLint для каждого слоя запрещаются импорты вышестоящих слоёв, **кроме** пути `@/app/store`
и его подпутей. Всё остальное из `app` закрыто так же, как для остальных верхних слоёв.

Публичное API стора (`app/store/index.ts`) отдаёт только: сам store, типизированные хуки и типы
`RootState` / `AppDispatch`.

## Почему

- **Один узкий контракт лучше правила с исключениями «на словах».** Запрет `@/app/**` действует везде;
  исключение ровно одно, оно записано в конфигурации и объяснено комментарием рядом.
- **Альтернатива B не улучшает архитектуру, а маскирует нарушение.** Перенести хуки в `shared` — значит
  признать, что нижний слой зависит от верхнего, и просто перестать это замечать.
- **Пропсы вместо стора не работают в thunk'ах.** Асинхронная логика живёт вне дерева компонентов и не
  может получать `dispatch` через контекст React.
- **Исключение не разрастается.** Через `@/app/store` доступны только хуки и типы; любые новые модули в
  `app` автоматически закрыты для нижних слоёв.

## Последствия

**Получаем:**

- компоненты читают состояние одной строкой и с полной типизацией;
- запрет импортов вверх сохраняется для всего, кроме одной явной точки;
- ответ на вопрос «почему фича импортирует app» зафиксирован в конфигурации и в этом документе.

**Платим:**

- правило границ содержит исключение, которое нужно держать узким при изменениях;
- при появлении второго стора (или нескольких провайдеров) исключение придётся пересматривать: путь
  `@/app/store` перестанет быть единственным.

## Когда пересмотреть

- Если приложение разделится на независимые части со своими сторами — исключение стоит заменить на
  явный список разрешённых контрактов.
- Если появится серверная отрисовка, где на каждый запрос нужен свой store, — схема с одним глобальным
  стором перестанет работать, и вопрос доступа к нему придётся решать заново.
