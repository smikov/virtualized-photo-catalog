# ADR 019: Контейнеризация — облегчённый образ для демонстрации и проверки

**Статус:** принято (пересмотрено; ранее — полноценный прод-образ с `npm run build`)

## Проблема

Нужно показать, что приложе��ие запускается в контейнере: одной командой, без локально настроенного
окружения. Контейнер используется для демонстрации и приёмки работы, а не для разработки.

Собираемый образ должен быть проще полноценного продакшн-образа, но при этом стабильным: без
HMR-перезагрузок, которые сбрасывают состояние приложения (загруженные данные, поиск, прогресс).

## Варианты

### A. Multi-stage: сборка в Node, раздача через nginx (облегчённая)

**Плюсы:** статика отдаётся стабильным nginx (никаких WebSocket/HMR), кэширование хешированных ассетов,
SPA-fallback, healthcheck. Сборка быстрее полной: без `tsc` и минификации (`vite build --minify false`).

**Минусы:** правки требуют пересборки образа; два сценария запуска (dev локально, контейнер — для показа).

### B. Один образ с dev-сервером и монтированием исходников

**Плюсы:** одна команда, работает горячая перезагрузка.

**Минусы:** **HMR-канал обрывается и перезагружает страницу во время демонстрации** — Docker Desktop
на Windows/macOS обрывает простаивающее TCP-соединение примерно через 15 с, Vite interprets это как потерю
сервера и перезагружает страницу вместе с данными и поиском. Для приёмки недопустимо.

### C. Без контейнера вообще

**Плюсы:** нечего поддерживать.

**Минусы:** теряется требование показать запуск в контейнере.

## Решение

Multi-stage образ: сборка статики в `node:26.13-alpine` (`npx vite build --minify false` — без typecheck
и минификации), раздача через `nginx:1.29-alpine` с отдельным конфигом.

1. Базовые образы используют ту же версию рантайма, что CI и `.nvmrc` (см. ADR 018).
2. Переменные `VITE_*` встраиваются в бандл на этапе сборки, поэтому передаются как build args.
   `environment` контейнера на них не влияет.
3. `index.html` отдаётся с `no-cache`, файлы из `/assets/` — с годовым `immutable`-кэшем: имена
   хешированы, а точка входа должна обновляться вместе со ссылками на новые имена.
4. Включены gzip, SPA-fallback и healthcheck.
5. Разработка остаётся локальной (`npm run dev`); контейнер — только демонстрация и проверка.

## Почему

- **Стабильность acima режима разработки.** Nginx не имеет механизмов, которые могут «ожить» и
  перезагрузить страницу посреди демонстрации.
- **Быстрая сборка.** Отказ от `tsc` и минификации ускоряет `docker compose up --build`; typecheck
  уже выполняется в локальных хуках и CI, поэтому дублировать его в образе не нужно.
- **Поведение близко к реальному окружению:** кэш, сжатие, SPA-fallback — как в проде.

## Последствия

**Получаем:**

- запуск одной командой на любой машине с Docker;
- отсутствие перезагрузок страницы во время демонстрации;
- более быструю сборку образа по сравнению с полным `npm run build`.

**Платим:**

- правки в контейнере требуют пересборки образа (в разработке контейнер не используется);
- бандл без минификации чуть больше, но для демонстрации это не критично.

## Когда пересмотреть

- Если контейнер снова понадобится для разработки — вернуть монтирование исходников отдельной целью
  сборки, не смешивая её с демонстрационной.
- Если появится реальный деплой — добавить полную продакшн-сборку (typecheck + минификация),
  TLS-терминацию и внешний кэш.
