# ADR 013: Стили и тематизация — CSS-модули и токены

**Статус:** принято

## Проблема

Нужно оформить приложение минималистично и аккуратно, при этом:

1. темизация должна быть через CSS-переменные (требование), то есть цвета и отступы не разбросаны по
   компонентам;
2. стили не должны протекать между компонентами;
3. нужны состояния, которые невозможно выразить инлайн-стилями: наведение, фокус с клавиатуры, анимации,
   `prefers-reduced-motion`.

## Варианты

### A. Инлайн-стили в JSX

**Плюсы:** всё рядом с разметкой; не нужно думать о классах; работает без настройки.

**Минусы:** недоступны псевдоклассы и медиазапросы; анимации невозможны; одинаковые стили копируются
между компонентами; правка дизайна размазана по всему коду; кэширование стилей отсутствует.

### B. CSS-модули + CSS-переменные

**Плюсы:** локальные имена классов без коллизий; псевдоклассы, анимации, медиазапросы; токены темы в одном
месте; ноль рантайма; файл стилей лежит рядом с компонентом.

**Минусы:** появляется дополнительный файл на компонент; переиспользование через `composes` работает
только внутри модулей; `@keyframes` скоупятся в каждом модуле отдельно.

### C. Tailwind CSS

**Плюсы:** быстро; утилиты не нужно изобретать; консистентные отступы.

**Минусы:** тема задаётся конфигурацией, а не CSS-переменными, — прямое противоречие требованию; разметка
забивается утилитами и хуже читается при нетривиальной вёрстке.

### D. CSS-in-JS (styled-components, emotion)

**Плюсы:** стили в одном файле с компонентом; тема через провайдер; динамические стили удобны.

**Минусы:** рантайм-стоимость на каждый рендер; лишние килобайты; переменные темы всё равно захочется
держать в CSS, и получится два механизма одновременно.

### E. Sass/Less

**Плюсы:** переменные, миксины, вложенность.

**Минусы:** переменные препроцессора не переключаются в рантайме — то есть темизация невозможна без
пересборки; для задачи хватает обычного CSS.

## Решение

1. **Токены темы** — CSS-переменные в глобальном файле: цвета, шрифт, отступы, радиусы, тени. В компонентах
   нет ни одного «магического» цвета.
2. **Стили компонентов — CSS-модули**: локальные имена, псевдоклассы, анимации.
3. **Переиспользование внутри слоя стилей** — через `composes` (например, кнопка и её опасный вариант).
4. **Анимации объявляются в том модуле, где используются:** CSS-модули скоупят `@keyframes`, глобальное
   объявление всё равно превратилось бы в локальную копию.
5. **`prefers-reduced-motion` учитывается** во всех анимациях (полоса прогресса, шиммер скелетона,
   появление изображения).

## Почему

- **Темизация — это про переменные, а не про инструмент.** Переопределив `:root` (или селектор темы), мы
  получаем вторую тему без правок компонентов. Tailwind и Sass этого не дают в нужном виде.
- **Инлайн-стили отпадают из-за требований интерфейса.** Кнопка с состоянием наведения, фокус с клавиатуры
  для доступности, скользящая полоса прогресса — всё это невозможно выразить инлайн-стилями.
- **Ноль рантайма.** CSS-модули не добавляют работы в браузер, в отличие от CSS-in-JS.
- **Один источник стилей на компонент.** Файл `.module.css` рядом с компонентом читается как его часть,
  а классы не конфликтуют с другими компонентами.

## Последствия

**Получаем:**

- вторую тему можно добавить переопределением переменных, не трогая компоненты;
- псевдоклассы, анимации и медиазапросы доступны в полном объёме;
- стили компонента изолированы: удаление компонента удаляет и его стили.

**Платим:**

- на каждый компонент — дополнительный файл;
- анимации дублируются по модулям (сознательно: единственная альтернатива — неявная связь между файлами);
- разработчику нужно знать два механизма: токены (`var(--...)`) и локальные классы.

## Когда пересмотреть

- Если появится дизайн-система с общими компонентами — часть стилей переедет в общий слой UI-примитивов.
- Если понадобится несколько тем с переключением в рантайме — достаточно добавить переопределение токенов
  по атрибуту; сам подход менять не потребуется.
